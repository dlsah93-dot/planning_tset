# 카페 판매·손익·재고 관리 프로그램 PRD

작성일: 2026-10-12  
상태: 사용자가 모든 추천안을 채택함. 1차 제품 범위와 제안한 운영 원칙은 확정했으며, 다음 단계의 계산식·설계·상세 처리 기준은 별도 미정이다.  
PRD는 제품이 해결할 문제와 필요한 기능을 정리한 문서다. MVP는 처음 사용할 수 있도록 만드는 최소 핵심 기능을 뜻한다.

## 1. 목적과 핵심 흐름

카페 운영자가 판매 기록을 입력하고, 메뉴별로 얼마나 남는지 확인한 뒤, 같은 기록을 바탕으로 기간 실적·손익과 재료 잔량을 확인할 수 있게 한다. 잘못 입력한 기록을 고쳐도 이 흐름이 이어져야 한다.

**판매 기록 입력 → 메뉴 수익성 확인 → 같은 기간의 손익과 기준일의 재료 잔량 확인**

운영자가 원하는 전체 기능은 판매·비용의 입력·수정·삭제, 엑셀 양식 다운로드와 기록 가져오기, 입고·폐기·실제 재고 기록, 부족 재료와 참고 발주량 확인, 예상 손익, 일·주·월·분기·반기·연간 조회, 저장·백업·복원이다. 사용자는 모든 추천안을 채택했다. 아래 1차·2차 구분은 그 선택을 반영하며, 2차 요구도 전체 제품 범위에 유지한다.

## 2. 검토한 자료와 확인 사실

검토 자료:

- `date/데이터설명.md`: 자료의 의미와 주의사항.
- `date/매장운영데이터.xlsx`: 실제 시트 이름·열·기록 확인.
- `date/매장운영데이터.json`: 전체 기록 구조·기간·종류 확인 및 엑셀과 대조.

공급사부터 비용기록까지 11개 기록 묶음의 행 수와 각 값을 대조했다. 날짜 표현과 빈칸 표현을 맞춰 비교했을 때 엑셀과 JSON의 값 차이는 없었다. 자료정보와 엑셀 안내 내용도 확인했다. 이는 두 형식이 같은 기록이라는 확인이며, 모든 사업상 기록의 정확성을 검증했다는 뜻은 아니다.

| 기록 | 확인한 수 | 담긴 내용과 의미 |
| --- | ---: | --- |
| 공급사 | 3 | 공급사 식별번호와 이름 |
| 재료 | 11 | g·ml·개 단위, 구매용량·최초가격, 공급사, 납기와 안전재고 일수 |
| 메뉴 | 8 | 메뉴명·판매기준가·분류·레시피 버전 |
| 레시피 | 22 | 메뉴 한 개에 필요한 재료와 사용량. 포장 판매에만 적용되는 재료도 있음 |
| 재료가격이력 | 33 | 적용시작일별 구매가격과 구매용량 |
| 영업달력 | 457 | 영업·휴무·마감 여부, 날씨·메모. 2026-09-30까지 있음 |
| 판매기록 | 6,112 | 일자·메뉴·매장/포장 채널별 판매수량, 당시 단가·할인·순매출·결제수수료·개당 원가 |
| 초기재고 | 11 | 2025-07-01 영업 시작 전 재료 수량 |
| 재고기록 | 1,515 | 입고 1,302건, 폐기 189건, 실사조정 24건. 실사는 실제 재료를 세어 보는 일 |
| 월비용계획 | 120 | 월별 비용항목과 금액 |
| 비용기록 | 3,560 | 월 비용을 날짜별로 나누어 기록한 비용. 실제 지출 건별 영수증 기록과는 구분해야 함 |
| 자료정보 | 10 | 매장명·출처·통화·기간 등. JSON에서는 `meta`에 대응 |

엑셀에는 별도의 `데이터안내` 시트도 있다. 데이터설명.md의 ‘엑셀 1행은 열 이름’ 설명은 기록 시트에 해당하며, 안내 시트는 설명문 형식이다.

추가 확인 사실:

- 프렙 카페의 **직접 구성한 가상 매장 샘플**이다. 실제 거래 자료가 아니다.
- 기록 시작은 2025-07-01, 마지막 마감일은 2026-09-18이다. 이후 12일은 영업달력만 있고 미마감 상태다.
- 금액은 원 단위이며 부가세 제외 금액이다. 재료 수량은 각 재료의 g·ml·개 단위를 따른다.
- 판매 채널은 매장과 포장이며 각각 3,056행이다. 판매 한 행은 주문 한 건이 아니라 일자·메뉴·채널별 집계다.
- 비용은 임차료, 인건비, 사업주 부담 보험료, 관리비, 수도광열비, 통신·소프트웨어, 광고비, 소모품·청소비의 8개 항목이다.
- JSON의 `settings`는 비어 있다. 수익성 분류·전망·비용 배분·재고 처리에 대한 합의는 자료에 없다.

## 3. 기획할 때 주의할 점

| 확인 사실 | 제품 기획에 미치는 영향 |
| --- | --- |
| 엑셀과 JSON은 같은 기록 | 둘을 각각 추가해 기록이 두 배가 되지 않도록 해야 한다. 처음 넣을 형식과 반복 가져오기 정책은 미정이다. |
| 월비용계획과 일별 비용기록은 같은 비용을 다른 단위로 기록 | 두 자료를 별도 지출처럼 더하면 안 된다. 계획·기록의 사용 목적을 구분해야 한다. |
| 미래 날짜는 미마감이며 연간 기록도 일부 기간만 존재 | 미기록을 판매 0으로 처리하지 않는다. 실제 기록의 포함 기간과 미완료 기간을 알 수 있어야 한다. |
| 판매 당시 원가·가격·수수료가 기록되어 있음 | 현재 가격을 바꿨다는 이유로 과거의 의미가 달라지지 않도록 해야 한다. 신규·수정 기록의 적용 기준은 별도 결정이 필요하다. |
| 포장에만 쓰는 재료가 있음 | 매장 판매와 포장 판매의 비용·재료 사용 차이를 놓치지 않아야 한다. |
| 구매가격은 한 묶음 가격, 레시피는 메뉴 한 개 사용량 | 구매용량·사용량·단위를 혼동하면 수익성과 잔량이 틀릴 수 있다. |
| 재고에는 증감수량과 실제로 센 수량이 함께 있음 | 실제 수량과 조정량을 같은 입고로 취급하지 않는다. 같은 날 판매·실사의 적용 기준은 미정이다. |
| 입고는 양수, 폐기는 음수, 실사조정은 양수·음수 모두 존재 | 유형과 수량의 의미를 유지해야 한다. 자료에 없는 값을 임의로 채우지 않는다. |
| 빈칸과 0은 다르며 납기·안전재고는 영업일 단위 | 정보가 없는 상태와 실제 0을 구분한다. 발주 참고 기능에서 휴무일을 고려할 필요가 있다. |
| 현재 자료는 가상 샘플이고 향후 운영 정책은 비어 있음 | 샘플의 기존 결과를 실제 매장의 확정 기준으로 채택하지 않는다. |

## 4. 확정한 1차 범위: 4시간 안의 핵심 기능

### 4.1 범위와 전제

사용자가 모든 추천안을 채택하여 **직접 입력과 재고 관리 우선인 A안**으로 확정했다. 앞서 보류했던 입력 방식도 이번 선택에 따라 1차 직접 입력·2차 엑셀 가져오기로 정리했다. 사용 환경은 **한 매장·한 사용자·한 사용 기기**이며 제공 자료의 기존 메뉴와 재료로 시작한다. 여러 기기 동기화와 공동 편집은 1차에 포함하지 않는다. 메뉴·레시피 변경 관리까지 포함하면 4시간 계획을 다시 잡아야 한다.

메뉴 수익성에는 식재료·포장재·결제수수료를 포함하고, 공통 운영비는 매장 전체 손익에서 고려한다. 과거 실적은 판매 당시 기준을 유지하며 현재 가격 변경만으로 자동 재평가하지 않는다. 비용은 해당하는 기간에 반영한다. 실제 재고를 확인하면 그 확인 시점의 수량을 기준으로 이후 잔량을 관리하고 기록상 수량과의 차이를 남긴다.

신규·수정 기록의 원가·수수료 기준, 나머지 비용과 재고의 상세 처리 기준은 다음 단계에서 다룬다. 이 문서는 계산식과 처리 절차를 정하지 않는다. 미정 사항을 확정 정책으로 간주하지 않으며, 구현 전에 필요한 기준을 정리해야 한다.

| 번호 | 1차 기능 | 사용자가 얻는 결과 | 제한 |
| --- | --- | --- | --- |
| P1-01 | 제공 자료로 시작하기 | 기존 메뉴·재료·레시피·가격·달력·판매·비용·재고를 바탕으로 핵심 흐름을 확인 | 최초 자료 준비만 포함. 사용자가 임의 엑셀·JSON을 반복 가져오는 기능은 2차 |
| P1-02 | 판매 기록 입력·수정·삭제 | 일자·메뉴·판매 채널별 판매 기록을 관리하고 변경을 수익성·손익·잔량에 반영 | 주문별 관리·결제 연동 제외. 신규 원가·수수료 등 적용 기준은 미정 |
| P1-03 | 비용 기록 입력·수정·삭제 | 지급일이 아니라 비용이 해당하는 기간을 기준으로 관리하고 손익에서 확인 | 월 계획 편집·자동 배분 제외. 직접 입력 비용과 기존 배분 비용의 관계는 미정 |
| P1-04 | 메뉴별 수익성 확인 | 메뉴별 판매 실적과 식재료·포장재·결제수수료를 고려한 남는 금액을 같은 기간 기준으로 비교 | 공통 운영비는 메뉴별로 나누지 않고 매장 전체 손익에서 고려. 좋음·나쁨 자동 등급은 2차 제안 |
| P1-05 | 일·월 실적과 손익 조회 | 기록이 있는 기간의 실적·비용·손익을 확인하고 미마감 기간을 구분 | 미래 예상 손익, 주·분기·반기·연간 묶음 조회는 2차 제안 |
| P1-06 | 입고·폐기·실제 재고 기록 및 잔량 확인 | 판매와 재고 기록이 연결된 잔량을 보고, 실제 확인 수량을 이후 재고 기준으로 사용하며 차이 기록을 남김 | 음수 잔량 등 기록상 이상을 식별. 앞으로 부족할 재료 판정·권장 발주량은 2차 |
| P1-07 | 저장·백업·복원 | 재접속 후 기록이 남고, 기록을 따로 보관했다가 되돌릴 수 있음 | 수동 백업·복원만 포함. 기기 간 공유·자동 백업 제외. 복원이 미치는 범위는 미정 |

‘재료 잔량’은 기록을 근거로 한 수량이다. ‘실제 재고’는 사용자가 센 수량이다. 둘을 구분해 확인할 수 있어야 한다. 아직 발생하지 않은 부족을 예측하는 기능은 1차 잔량 확인과 구분한다.

### 4.2 4시간 작업 예산

| 작업 | 시간 | 완료 목표 |
| --- | ---: | --- |
| 기획과 필수 결정 | 25분 | 1차 범위·사용 환경·필수 사업 기준 합의 |
| 화면 설계 | 30분 | 핵심 흐름에 필요한 화면 구성 정리. 실제 디자인은 다음 단계에서 결정 |
| 개발 | 130분 | 확정한 1차 기능 구현 |
| 검사 | 35분 | 핵심 흐름, 기록 변경, 자료 중복·기간·단위, 저장·복원 확인 |
| 배포 | 20분 | 합의한 사용 환경에 제공하고 실제 실행 확인 |
| 합계 | **240분** | 기획부터 배포까지 포함 |

이 시간은 단순한 첫 버전을 위한 작업 예산이며 완료 보장이 아니다. 외부 서비스 연결이나 배포 환경 준비가 필요해지는지 먼저 확인해야 한다. 초과가 예상되면 핵심 흐름과 저장·복원 검사를 유지하면서 확장 범위를 줄인다. 이번 요청에서는 PRD만 작성하며 화면 설계·개발·배포를 수행하지 않는다.

## 5. 2차 확장 기능

아래 기능도 전체 제품 요구에 포함된다. 사용자의 추천안 채택에 따라 4시간 첫 버전 이후로 미룬 기능이며 삭제된 요구가 아니다. 2차의 상세 범위와 작업 시간은 해당 단계에서 검토한다.

| 확장 기능 | 목적 | 뒤로 미루는 이유 |
| --- | --- | --- |
| 판매·비용 엑셀 양식 다운로드와 가져오기 | 여러 기록을 한 번에 입력 | 양식 일치·잘못된 값·기존 기록 중복·수정 여부를 함께 결정하고 검사해야 함 |
| 재고 기록 엑셀 가져오기와 자료 재가져오기 | 기존 운영 자료를 계속 활용 | 초기재고·실사·판매가 함께 변할 때 결과의 일관성 확인 필요 |
| 주·분기·반기·연간 조회 | 운영 주기별 실적 확인 | 주 시작일·기간 경계·불완전 기간의 의미를 합의할 필요가 있음 |
| 예상 손익 | 아직 마감되지 않은 기간의 전망 확인 | 예상의 대상 기간·가정·실적과의 구분을 먼저 결정해야 함 |
| 부족 예상 재료와 권장 발주량 | 다음 영업에 필요한 재료 준비 | 수요 기준·납기·휴무·안전재고·구매 묶음의 의미를 합의해야 함 |
| 메뉴·레시피·가격이력 관리 | 신메뉴와 원가 변화 대응 | 변경 전후 과거 기록의 의미를 보존하는 기준 필요 |
| 월비용계획 편집·기간별 배분 | 비용 계획과 실적 관리 | 계획과 기록의 중복을 막고 직접 입력 비용과의 관계를 정해야 함 |
| 수익성 등급·기간 비교·원인 분석 | 잘 팔리는 메뉴와 개선할 메뉴 파악 | 등급 기준과 비교 가능한 기간을 정해야 함 |
| 자동 백업·여러 기기 공유·공동 사용 | 운영 편의 확대 | 사용자 구분·동시 변경·복원 범위 등 추가 요구가 생김 |

## 6. 1차 완료 판단 기준

구현 전 합의된 기준으로 다음을 확인한다. 수치의 정답과 상세 검사 절차는 이후 단계에서 작성한다.

1. 판매 기록을 추가하고 해당 메뉴의 수익성, 해당 기간의 손익, 관련 재료의 잔량을 이어서 확인할 수 있다.
2. 판매를 수정·삭제하면 연결된 결과가 일관되게 바뀌며 이전 기록이 중복 반영되지 않는다.
3. 비용을 추가·수정·삭제하면 기간 손익에 반영되고 월비용계획을 별도 지출로 중복 반영하지 않는다.
4. 매장·포장 판매에 적용되는 재료 차이를 확인할 수 있다.
5. 입고·폐기·실제 재고 기록의 의미가 구분되고 재료별 단위가 유지된다. 실사 처리의 정답은 합의한 정책으로 판단한다.
6. 일·월 조회에서 조회 기간과 기록 포함 기간을 알 수 있고, 미마감 날짜와 누락 정보를 실제 0으로 오해하지 않는다.
7. 저장 후 재접속해 기록을 확인할 수 있고, 백업·복원 후 판매·비용·재고와 기준정보가 합의한 범위에서 유지된다.
8. 배포한 사용 환경에서도 이 흐름을 완료할 수 있다.

## 7. 확정 사항과 미정 사항

### 사용자 요청으로 확정된 방향

- 카페 판매·재고·비용을 연결하는 웹 프로그램을 기획한다.
- 판매 입력에서 메뉴 수익성, 손익과 잔량 확인으로 이어지는 흐름에 집중한다.
- 1차·2차 기능을 나누고 1차는 기획·설계·개발·검사·배포를 합쳐 4시간 수준으로 제안한다.
- 이번 PRD에서는 계산식·화면 디자인·기술 선택·상세 동작·코드를 정하지 않는다.
- 1차 사용 환경은 한 매장·한 사용자·한 사용 기기다.
- 사용자가 모든 추천안을 채택하여 입력 방식 보류를 해제했다. 1차는 직접 입력과 재고 관리에 집중하고 엑셀 양식·가져오기는 2차에 구현한다. 4절과 5절의 단계 구분을 채택했다.
- 메뉴 수익성에는 식재료·포장재·결제수수료를 포함한다. 임차료·인건비 등 공통 운영비는 메뉴별로 나누지 않고 매장 전체 손익에서 고려한다. 사용자가 비용 범위 질문의 추천안 A를 선택했다. 폐기 등 나머지 비용의 처리 기준은 별도 미정이다.
- 과거 실적은 판매 당시의 가격·원가·수수료 기준으로 유지한다. 현재 가격이 바뀌어도 과거 실적을 자동 재평가하지 않는다. 사용자가 과거 실적 기준 질문의 추천안 A를 선택했다. 잘못된 기록의 수정까지 막는 결정은 아니다.
- 비용은 실제 지급일이 아니라 비용이 해당하는 기간의 손익에 반영한다. 예를 들어 9월 임차료를 10월에 지급해도 9월 비용으로 본다. 사용자가 비용 반영 기간 질문의 추천안 A를 선택했다. 일별 배분 방법과 기존 비용·직접 입력 비용의 관계는 별도 미정이다.
- 실제 재고를 확인하면 그 확인 시점의 수량을 이후 잔량 관리의 기준으로 사용하고 기록상 수량과의 차이도 남긴다. 사용자가 모든 추천안을 채택하면서 실제 재고 활용 질문의 A안도 선택했다. 확인 시점과 과거 수정의 상세 처리 기준은 별도 미정이다.

## 8. 다음 단계에 남겨 둔 내용

이번 문서는 자료 확인, 제품 목적, 1차·2차 범위, 사용자가 채택한 운영 원칙, 완료 판단 기준을 정리한다. 이전의 질문별 선택지는 결정 사항으로 통합했다.

다음 단계에서는 계산식, 화면 구성과 디자인, 기술, 입력 항목과 오류 처리, 가격·원가 적용, 재고 기록의 적용 순서, 백업·복원의 상세 동작, 검사 절차, 배포 방법을 정리한다. 이 내용은 이번 문서에서 확정하지 않는다.

4시간 작업 예산에는 이러한 다음 단계의 기획·설계 작업도 포함된다. 미정 기준이나 사용 환경 준비로 시간이 늘어날 경우, 완료 보장으로 취급하지 않고 핵심 흐름과 필수 검사를 유지할 수 있는 범위로 다시 검토한다.
