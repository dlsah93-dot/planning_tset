# 카페 판매·손익·재고 관리 기능 요구사항 문서(FRD)

작성일: 2026-10-12  
상태: 사용자 요청 ‘추천대로 진행하고 문서를 완성’에 따라 1차에 필요한 권장 동작과 계산 기준을 채택한 문서. 2차 기능은 향후 범위로 구분한다.  
FRD는 사용자의 행동에 따라 프로그램이 무엇을 처리하고 어떤 결과를 보여 주는지 정리한 문서다. 구현 코드는 포함하지 않는다.

## 1. 목적·범위·읽는 방법

한 매장의 한 사용자가 한 기기에서 판매·비용·재고 기록을 관리한다. 핵심 흐름은 **판매 입력 → 메뉴별 수익성 확인 → 같은 기간 손익과 재료 잔량 확인**이다.

- **PRD 확정:** 기존에 승인한 기능 범위와 운영 원칙.
- **자료·시안 확인:** 실제 파일에 있는 항목이며 합의된 동작이나 정답을 뜻하지는 않는다.
- **채택한 권장 기준:** 이번 FRD에서 구체화한 동작·계산·오류 대응. 사용자의 추천안 진행 요청에 따라 채택했으며 자료에서 확인한 사실과 구분한다.
- **2차:** 전체 제품 요구에는 남아 있으나 1차에서 작동시키지 않는 기능.
- **승인되지 않은 추가 기능:** 시안에만 있는 기능. 이번 문서가 구현 승인을 대신하지 않는다.

1차는 제공 자료 준비, 판매·비용 입력·수정·삭제, 메뉴 수익성, 일·월 실적과 손익, 입고·폐기·실제 재고 기록, 잔량 확인, 저장·수동 백업·복원이다. 기획·설계·개발·검사·배포를 포함한 4시간 작업 예산을 유지한다. 추가 기능으로 범위를 늘리지 않는다. 기술 선택은 별도이며 시안에 등장하는 기술 이름을 확정하지 않는다.

## 2. 검토 자료와 한계

기준 문서는 `docs/01_PRD.md`다. `design/01_prd.md`는 앞뒤 공백을 제외하면 같은 내용이다. `design/espresso_ledger_admin/DESIGN.md`도 읽었으며, 색·글꼴 등 시각 규칙과 여러 매장·실시간 연동 같은 기능 표현을 제품 승인과 구분했다. 자료의 의미는 `date/데이터설명.md`와 `date/매장운영데이터.json`을 다시 확인했다.

각 아래 폴더의 `code.html`에서 버튼·입력칸·선택항목·설명·결과 표시를 검토했다. 이미지 확인 범위는 다음과 같다.

| 시안 폴더 | 기능 | 이미지 확인 결과 |
| --- | --- | --- |
| `dashboard_period_p_l` | 기간 손익 대시보드 | `screen.png`가 이미지가 아닌 `<FIFE Image failed to fetch>` 내용. HTML로 검토 |
| `sales_ledger` | 판매 목록 | PNG 확인. 오른쪽 일부 표 내용은 이미지에서 잘려 HTML로 보완 |
| `sales_modal` | 판매 입력 | PNG와 HTML 확인 |
| `menu_profitability` | 메뉴 수익성 | PNG가 정상 이미지가 아니어서 HTML로 검토 |
| `expenses_modal` | 비용 입력·수정 | PNG와 HTML 확인. 별도 비용 목록 시안은 없음 |
| `inventory_stock_audit` | 재고 목록·입고·폐기·전체 실사 | PNG가 정상 이미지가 아니어서 HTML로 검토 |
| `inventory_modal` | 재료별 실사 | PNG와 HTML 확인 |
| `backup_restore` | 백업·복원 | PNG가 정상 이미지가 아니어서 HTML로 검토 |
| `restore_modal` | 복원 최종 확인 | PNG에는 흐린 배경만 보임. 확인창 내용은 HTML로 검토 |

HTML에 버튼이나 성공 메시지가 있다는 것은 시안의 표현을 확인했다는 뜻이다. 실제 저장·계산·복원 기능이 구현되거나 검증되었다는 뜻은 아니다. 원본 PRD·자료·시안 파일은 변경하지 않았다.

## 3. PRD와 시안의 차이 및 처리 방향

권장 방향은 PRD의 1차 범위를 유지하고, 시안의 예시 숫자·새 기능을 확정 요구로 사용하지 않는 것이다. 사용자의 추천안 진행 요청에 따라 아래 방향을 채택한다.

| 차이 | 확인한 내용 | FRD 처리 방향 |
| --- | --- | --- |
| 순매출 정의 | 판매·대시보드 시안은 수수료 차감 후 금액을 순매출이라 부름. 메뉴 시안은 순매출에서 수수료를 다시 차감하는 식을 제시 | 순매출은 할인 후·수수료 차감 전 금액. 수수료는 한 번만 별도 차감. 화면 용어와 계산 안내 수정 필요 |
| 수수료율 | 시안은 2.5% 일괄 적용. 자료는 금액을 별도 보관하며 약 1.5% 수준 | 기존 금액 그대로 유지. 신규 기본율은 1.5%를 권장 기준으로 채택하고 판매 입력에서 변경 가능 |
| 메뉴·재료·가격 | 시안은 아인슈페너·자몽·별도 컵·뚜껑 등 다른 예시와 가격을 사용 | 제공 자료의 메뉴 8개·재료 11개·레시피 22개·가격이력을 사용. 포장 원가를 120원·135원으로 고정하지 않음 |
| 시간·주문 정보 | 판매 시안은 판매 시각·주문 검색·시간대 분석·POS 동기화를 표시 | 자료는 날짜·메뉴·채널별 집계. 판매 시각·주문번호·시간대 분석·POS 연동은 1차에 추가하지 않음 |
| 기간과 영업일 | 시안은 2026-09-01~18을 18영업일로 표시하고 누적 기록 기간을 457일로 표시 | 달력으로 집계. 9월 1~18일의 마감 영업일은 실제 16일. 달력 전체 457일과 9월 18일까지의 기록 기간을 구분 |
| 전망·발주 | 대시보드의 예상 이익·안전재고·즉시발주, 재고의 예상 소진일·발주 초안 | 전망·부족 예상·참고 발주량은 2차. 실제 발주 실행은 PRD에 없어 승인 없이 추가하지 않음 |
| 판매 임시 저장 | 판매 입력에 별도 버튼 있음 | 임시 초안 보관은 미승인 추가 기능. 1차는 확정 저장·취소만 사용 |
| 비용 입력 | 시안은 귀속월·실제 지급일·지급수단·거래처·예산 분석을 표시 | 1차는 귀속일·비용항목·금액으로 관리. 귀속월은 날짜에서 알 수 있음. 지급·증빙 상세와 예산 분석은 추가하지 않음 |
| 비용 관리 화면 | 메뉴에는 있으나 독립된 목록 시안 없음 | 필수 수정·삭제를 위한 비용 목록 요구를 FRD에 명시. 새로운 제품 기능이 아닌 PRD 필수 기능의 누락 보완 |
| 실사 범위 | 전체 실사창은 5개 입력칸만 있고 ‘기타 6종 정상’ 표시 | 미입력 재료를 확인한 것으로 처리하지 않음. 1차는 재료별 실사. 전체 일괄 실사·전수 확정은 미승인 보조 기능 |
| 재고 단위 | 시안에 우유 팩·kg·개가 혼재 | 1차 입력·저장은 자료의 g·ml·개 기준. 임의 팩 변환은 추가하지 않음 |
| 음수·재고 차이 비용 | 시안은 음수 차단, 실사 차이 자동 손실 처리를 승인된 것으로 표현 | 음수 기록상 잔량은 경고하고 기록을 숨기지 않음. 실제 실사량은 음수 불가. 폐기·차이의 금액 손익 반영은 아래 제한 기준 사용 |
| 백업 범위와 자동화 | 선택 백업·CSV ZIP·익명화·자동 스케줄·복원점 이력·해시·압축 표시 | 1차는 전체 JSON 수동 백업·전체 교체 복원. 선택 추출·익명화·예약·복원점 관리·압축 파일은 추가하지 않음 |
| 복원 확인 문구 | 백업 화면은 ‘프렙카페복원’, 별도 창은 ‘복원확인’ | 한 문구 ‘복원확인’으로 통일하고 빈 입력칸으로 시작 |
| 기술·용량·검증 표시 | SQLite와 IndexedDB 혼용, 50MB/250MB 혼용, 정합성 100% 예시 | 기술 미확정. 파일 허용 크기는 아래 기준 사용. 실제 검사 전 ‘정상·100%·저장 완료’를 표시하지 않음 |
| 보고서와 분석 | 인쇄·CSV 저장·일괄 정산 검증·프로모션·등급·손익분기 매출 | 1차 필수 범위를 넘는 기능은 추가하지 않음. PRD에 있는 확장 분석만 2차에 유지 |

자료의 6,112개 판매 전부에서 `순매출 = 수량 × 판매단가 − 할인금액`이 맞았다. 첫 판매는 20개 × 4,000원, 순매출 80,000원, 수수료 1,200원이다. 이 자료 사실을 수수료를 중복 차감하지 않는 권장안의 근거로 사용한다.

## 5. 모든 기능에 적용하는 채택 기준

### 5.1 기록·입력 기준

- 금액은 원·부가세 제외다. 부가세 계산·신고·매입세액 공제 판단은 하지 않는다.
- 판매 한 행은 일자·메뉴·채널별 합계다. 같은 조합의 신규 행은 막고 기존 행 수정으로 안내한다. 여러 주문별 입력 기능을 만들지 않는다.
- 비용 한 행은 귀속일·항목별 합계다. 같은 조합을 다시 입력하면 기존 합계를 수정하도록 안내한다. 실제 지급일이 아닌 귀속일이 일·월 손익의 기준이다.
- 날짜는 한국 날짜 기준. 기록 시작일 2025-07-01부터 오늘까지 등록 가능하다. 미래 실적 입력은 막는다. 자료에 있는 미래 달력은 그대로 유지한다.
- 신규 입력의 기본 날짜는 오늘, 첫 조회의 기본 기간은 판매 기록이 존재하는 가장 최근 월이다. 기간을 바꾸면 해당 화면의 요약과 목록을 같은 기준으로 갱신한다.
- 판매수량·‘개’ 단위 수량은 정수. 판매수량은 1 이상, 입고·폐기량은 0 초과, 실제 재고 수량은 0 이상이다. g·ml는 소수 셋째 자리까지 허용한다.
- 판매단가·할인·비용은 원 단위 정수로 입력한다. 단가는 0 이상, 할인은 0 이상이고 총 판매금액 이하, 비용 금액은 0 초과다. 0원 무료 판매는 허용하되 비율은 계산 불가로 표시한다.
- 빈칸은 0이 아니다. 필수 값이 비면 해당 항목에 오류를 보여 주고 저장하지 않는다. 화면의 샘플 숫자를 실제 입력값으로 간주하지 않는다.
- 처음 자료의 기록번호를 보존한다. 새 기록에는 겹치지 않는 번호를 부여한다. 수정은 같은 번호를 유지하며 새 판매·비용을 추가한 것처럼 처리하지 않는다.

### 5.2 저장·결과 기준

- 입력 중 계산은 미리보기다. 저장 버튼을 누르기 전에는 실제 기록·집계·재고를 바꾸지 않는다.
- 저장 성공 후 연결된 결과를 함께 갱신한다. 판매만 저장되고 재고는 갱신되지 않는 부분 성공을 정상으로 표시하지 않는다.
- 저장 중 중복 클릭을 막는다. 실패하면 이전 기록·결과를 유지하고 입력값을 남겨 재시도할 수 있게 한다. 저장 성공이 확인되어야 ‘저장 완료’를 표시한다.
- 취소·닫기는 저장하지 않는다. 입력이 바뀌었다면 버릴지 확인한다. 별도 임시 저장 기능은 만들지 않는다.
- 수정·삭제는 대상과 영향 범위를 확인한 뒤 반영한다. 삭제 취소는 기존 상태를 유지한다. 별도 휴지통·삭제 이력 관리 기능은 추가하지 않는다.
- 화면 조회만으로 파일은 생성되지 않는다. 1차 파일 출력은 수동 전체 백업 JSON뿐이다. 화면 표 CSV·인쇄·엑셀은 1차 출력에 포함하지 않는다.
- 필요한 정보가 없어 계산할 수 없는 값을 0으로 채우지 않는다. ‘계산 불가’와 빠진 정보를 표시한다. 일부 값만 확인되면 부분 결과임을 알린다.

## 6. 기능별 상세 요구사항

### F01. 처음 자료 준비와 기준정보

**행동:** 프로그램을 처음 연다. 사용자가 자료를 반복 업로드하는 기능은 1차에 없다.

**처리:** 제공 엑셀 또는 JSON 중 하나를 준비 자료로 사용한다. 공급사 3개, 재료 11개, 메뉴 8개, 레시피 22개, 가격이력 33개, 달력 457일, 판매 6,112개, 초기재고 11개, 재고기록 1,515개, 월비용계획 120개, 비용 3,560개와 자료정보를 확인한다. 모든 참조 번호·단위·기록번호를 검사한다. 이미 저장한 운영 기록이 있으면 초기 자료를 다시 추가하지 않는다.

**결과:** 기존 실적·재고를 바로 조회할 수 있다. 화면과 백업에서 가상 샘플 자료라는 출처를 유지한다. 기준정보는 1차에 조회·사용만 하며 메뉴·레시피·가격 수정 버튼을 추가하지 않는다.

**오류:** 필수 자료가 없거나 번호 연결이 끊기면 초기 준비를 중단하고 문제 묶음과 원인을 알린다. 기존 저장 기록은 유지한다. 오류 난 일부 자료를 빈 목록으로 바꾸어 ‘준비 완료’로 표시하지 않는다.

### F02. 판매 목록

**행동:** ‘판매 기록 관리’로 이동해 일·월 기간을 선택한다. 시안의 검색·채널·분류·정렬·쪽 나누기는 목록을 확인하는 보조 동작으로 사용한다.

**입력·처리:** 메뉴명 또는 판매 기록번호 검색, 전체/매장/포장 채널, 메뉴 분류 음료/디저트를 함께 적용한다. 주문번호는 검색 대상이 아니다. 날짜 최신순, 같은 날짜는 기록번호순으로 표시한다. 쪽당 10/25/50/100개 선택과 처음·이전·번호·다음·마지막 버튼은 목록만 바꾼다. 필터 변경 시 첫 쪽으로 돌아간다. 새로고침은 저장된 기록을 다시 읽으며 재고를 다시 차감하지 않는다.

**결과:** 날짜·기록번호·메뉴·채널·수량·당시 단가·할인·순매출·수수료·식재료비·포장재비·남는 금액·비율·수정·삭제를 표시한다. 검색 결과 전체 합계와 현재 쪽 합계를 구분한다. 날짜만 있는 자료에 임의 시간을 붙이지 않는다. 거래 수와 판매수량을 구분한다. 파일은 생성하지 않는다.

**오류:** 결과가 없으면 ‘조건에 맞는 기록 없음’을 표시한다. 이전 쪽의 숫자를 남기지 않는다. 삭제로 마지막 쪽이 비면 유효한 이전 쪽으로 이동한다. 잘못된 기간은 조회하지 않고 입력 오류를 알린다.

### F03. 판매 추가

**행동:** 공통 ‘판매 기록’ 또는 ‘신규 판매 기록 입력’을 누른다.

**입력:** 판매일·메뉴·매장/포장·판매수량·판매단가·할인 총액·결제수수료율. 날짜·메뉴·채널·수량·단가는 필수이며 할인 기본값은 0, 신규 수수료율 기본값은 1.5%다. 수수료율은 0~100% 범위에서 소수 둘째 자리까지 입력할 수 있다. 자료에 메뉴 Ice/Hot 구분이 없으므로 선택지를 새로 만들지 않는다.

**처리:** 해당 날짜의 레시피와 재료가격으로 개당 원가를 구하고 채널에 맞는 재료 사용량을 계산한다. 단가 초깃값은 해당 메뉴의 제공 기준가다. 사용자가 당시 단가로 수정할 수 있다. 원가·재료 사용량은 아래 C01·C02·C05 기준으로 미리 보여 준다. 포장 버튼의 ‘+120원’은 고정 금액 대신 실제 포장재 원가 안내로 바꾼다.

**저장 결과:** 날짜·메뉴·채널·수량·단가·할인·순매출·수수료 금액·레시피 버전·당시 개당 식재료/포장 원가를 보관한다. 판매 목록·메뉴 수익성·기간 손익·재료 잔량을 함께 갱신한다. 저장이 완료된 뒤에만 입력창을 닫는다. 별도 파일은 생성하지 않는다.

**오류:** 중복 조합은 기존 기록 수정으로 안내한다. 할인 초과·음수·소수 판매수량·선택 메뉴 없음은 저장 불가. 가격이력·레시피·재료 연결이 없거나 구매용량이 0이면 계산 오류를 표시하고 저장하지 않는다. 계산상 재고가 음수가 되어도 실제 판매 기록은 저장하고 해당 재료의 기록상 음수 잔량을 경고한다. 재고 부족을 숨기려고 판매를 버리거나 잔량을 0으로 맞추지 않는다.

### F04. 판매 수정·삭제

**행동:** 목록 행의 수정 또는 삭제를 누른다.

**수정 처리:** 기존 값을 입력창에 읽는다. 원가·수수료를 현재 기준으로 무조건 바꾸지 않는다. 수량·단가·할인만 수정하면 기존 개당 원가를 유지한다. 기존 수수료를 순매출로 나눈 비율을 내부 기준으로 유지하고 새 순매출에 적용한다. 원본의 순매출이 0이면 기존 수수료가 0일 때 0%로 시작한다. 0원 매출에 수수료가 있거나 비율을 알 수 없으면 비율을 직접 확인하도록 한다. 화면에 보이는 비율 반올림만으로 기존 금액을 바꾸지 않는다.

날짜·메뉴·채널을 바꾸면 바뀐 날짜·대상의 레시피·원가를 적용한다. 수수료율을 직접 바꾸면 입력율을 사용한다. 수정하지 않은 기록의 당시 값은 유지한다. 아무 값도 바꾸지 않고 저장하면 원본을 그대로 둔다.

**삭제 처리:** 대상 날짜·메뉴·채널·수량을 보여 주고 확인 후 제거한다. 취소하면 유지한다.

**결과:** 같은 기록번호의 수정 또는 삭제가 결과에 한 번만 반영된다. 재고는 기존 차감을 되돌린 뒤 새 차감을 중복 추가하는 방식이 아니라, 아래 실사 기준을 포함해 영향을 받는 재료의 흐름을 다시 구성한다. 실사 전 판매를 고쳤다고 실사로 확인한 실제 수량까지 바꾸지 않는다.

**오류:** 대상이 이미 없거나 변경 조합이 다른 기록과 겹치면 반영하지 않는다. 재계산·저장 실패 시 기존 기록을 유지하고 오류를 알린다. 과거 마감일의 기록 변경은 그날을 ‘변경 후 확인 필요’로 표시한다. 영업 마감·재마감 버튼은 1차에 새로 추가하지 않는다.

### F05. 비용 목록·등록·수정·삭제

**행동:** 비용 관리 메뉴에서 일·월별 목록을 보고 ‘신규 비용 입력’, 행별 수정·삭제를 사용한다. ‘이전 비용 내역 확인’은 목록으로 이동한다.

**입력:** 귀속일, 제공 자료의 8개 비용항목 중 하나, 부가세 제외 금액. 귀속월은 귀속일에서 결정한다. 1차에는 월 총액 자동 일별 배분이 없으므로 귀속월만 입력하고 일별 손익을 임의 배분하지 않는다. 시안의 실제 지급일·지급수단·거래처·증빙 비고·예산전액·예산 분석은 1차 입력에 포함하지 않는다. 빠른 ‘+10만/+50만/+100만’ 버튼은 금액칸을 그만큼 늘리며 저장은 하지 않는다.

**처리:** 기존 자료의 일별 배분 비용도 이미 반영된 비용이다. 동일 귀속일·항목의 값을 다시 입력하려 하면 기존 합계 수정으로 안내한다. 월비용계획을 비용기록과 함께 차감하지 않는다. 예를 들어 9월 18일 광고비 합계가 10,000원인데 별도 광고비 5,000원이 더 들었다면 기존 행을 15,000원으로 수정한다. 기존 10,000원이 잘못된 값이라면 올바른 총액으로 수정한다. 중복이라고 자동 덮어쓰지는 않는다.

**결과:** 귀속일·항목·금액·자료의 배분기준을 목록에 표시하고 기간 합계를 보여 준다. 신규 직접 기록의 배분기준은 ‘직접 입력’으로 구분한다. 수정·삭제는 비용 합계와 기간 손익만 바꾸며 메뉴 수익성·재료 잔량을 바꾸지 않는다. 월 계획은 참고 자료로 보존하고 1차에서 편집·집행률 계산은 하지 않는다.

**오류:** 귀속일 누락·미래 일자·미등록 항목·0 이하 금액·숫자 해석 실패는 저장 불가. 쉼표 금액은 유효한 숫자로 확인 후 처리한다. 기록이 없으면 비용 기록 없음과 확인 필요를 표시하며 비용이 실제로 없었다고 단정하지 않는다. 삭제 확인·실패 대응은 F04와 같다.

### F06. 메뉴별 수익성

**행동:** 메뉴 수익성으로 이동해 일·월 기간과 전체/매장/포장 채널을 선택한다. 이익 높은 순·판매량 많은 순·이익률 높은 순·원가율 낮은 순으로 정렬할 수 있다.

**처리:** 해당 기록의 당시 값으로 C02를 계산한다. 공통 운영비를 메뉴별로 나누지 않는다. 서로 다른 판매단가·원가가 섞이면 판매수량을 기준으로 평균을 구한다. 모든 메뉴가 항상 같은 가격·원가로 판매되었다고 가정하지 않는다.

**결과:** 메뉴·판매수량·평균 단가·평균 할인 후 매출·평균 식재료비·포장재비·수수료·개당 남는 금액·기간 남는 금액·이익률을 표시한다. 평균이라는 사실을 표기한다. 전체 합계는 F07의 같은 기간·전체 채널 메뉴 이익과 일치해야 한다. 1차에는 효자 등급·원가점검 자동 판정·전월 비교·프로모션 권고·시뮬레이션·CSV·인쇄를 추가하지 않는다.

**오류:** 판매량 0인 메뉴는 미판매로 표시하며 개당 값은 ‘해당 없음’이다. 순매출 0이면 이익률을 계산하지 않는다. 원가 누락은 계산 불가로 표시하며 유효한 메뉴만의 합계를 전체 정답처럼 표시하지 않는다. 이익이 음수인 경우 음수 그대로 보여 준다.

### F07. 일·월 실적과 손익

**행동:** ‘일간 실적’·‘월간 실적’과 날짜·월 선택을 사용한다. 비용원장 열람은 동일 기간 비용 목록으로, 메뉴 분석·실사 이동은 관련 화면으로 이동한다.

**처리:** C03으로 해당 기간의 기록된 판매·비용을 집계한다. 완료 여부는 달력의 마감 상태를 사용한다. 마감 영업일·마감 휴무일·미마감·달력 정보 없음·변경 후 확인 필요를 구분한다. 새 날짜에 저장한 기록은 달력이 없으면 ‘마감 정보 없음’이며 판매 저장만으로 마감 완료를 만들지 않는다.

**결과:** 총 판매금액·할인·순매출·수수료·식재료비·포장재비·메뉴 이익·공통 운영비·기록 기준 손익을 보여 준다. 확정된 날짜의 결과와 미마감/미확인 날짜의 입력 결과를 구분하고, 함께 합치면 ‘미확정 기록 포함’이라고 표시한다. 선택 기간·기록 포함 기간·마감 영업일 수를 표시한다. 미래 미기록 날짜는 0원으로 합치지 않는다. 그래프를 사용한다면 미기록 날짜는 빈 구간으로 표시한다. 잔량은 월 합계가 아닌 기준일 시점 값이며 월 조회의 기준일은 선택 월 안의 마지막 재고 관련 기록일이다.

계산 결과의 명칭은 ‘기록 기준 손익’이다. 세금·감가상각·금융비용·폐기 금액까지 모두 포함한 공식 회계이익으로 표현하지 않는다. 예상 손익·안전재고·발주·목표 달성·전월 비교·인쇄·엑셀 버튼은 1차에 작동시키지 않는다.

**오류:** 마감된 영업일에 판매행이 하나도 없으면 ‘판매 기록 확인 필요’를 표시한다. 원본에서 확인된 0 판매행과 미기록은 구분한다. 휴무·마감 완료 날짜에는 판매 없음과 0 판매를 혼동하지 않는다. 부분 기간의 일평균은 확정 영업일만 분모로 사용한다. 확정 영업일이 0이면 일평균은 계산 불가다. 판매는 있으나 비용이 빠진 날짜는 손익에 비용 확인 필요를 표시한다.

### F08. 재료 잔량과 변동 확인

**행동:** 재고 관리에서 기준일·재료 검색을 사용하고, 행의 ‘변동 기록’ 또는 전체 변동 기록 열람으로 관련 기록을 본다.

**처리:** C05에 따라 기준일까지의 판매 사용량·입고·폐기·실사를 연결한다. 재료명과 공급사 검색은 제공 자료 기준이다. 재료 분류는 자료에 없으므로 시안의 임의 분류·개수는 쓰지 않는다. 기본 정렬은 재료 번호순이다.

**결과:** 재료·공급사·g/ml/개·기준일 잔량·해당 기간 입고·판매 사용·폐기·마지막 실제 확인 일자와 수량을 보여 준다. 최근 변동은 유형·일자·재료·증감·실측량·사유로 확인한다. 음수는 기록 이상 경고, 0은 잔량 없음으로 표시한다. 양수라는 이유만으로 다음 영업에 충분하다고 판정하지 않는다. 분류·안전재고 필터·예상 소진일·발주 초안·CSV·재고차이의 금액 카드는 1차에 추가하지 않는다.

**오류:** 초기재고·레시피 연결·단위가 없거나 다르면 해당 재료를 계산 불가로 표시한다. 음수 잔량은 실제로 음수 물량이 있다는 뜻이 아니라 누락·오입력 가능성이 있다는 안내를 한다. 실사·입고를 확인하도록 안내하되 자동 가상 입고를 만들지 않는다.

### F09. 입고·폐기 등록

**행동:** ‘재고 변동’·‘입고/폐기 등록’에서 유형을 선택한다. 유형 변경은 계산 미리보기만 바꾼다.

**입력:** 일자·재료·입고량 또는 폐기량·사유. 재료 단위는 고정이다. 입고는 공급사 기본값을 제공 자료에서 가져온다. 입력량은 두 유형 모두 양수이며 프로그램이 입고 +, 폐기 −로 보관한다. 단위원가는 자료에 있으면 보존하지만 1차에 구매대금·미지급금 기능을 만들지 않는다.

**처리·결과:** C05·C06으로 변경 후 잔량을 미리 보여 주고, 저장 후 재고기록·변동 목록·관련 잔량을 갱신한다. 입고·폐기 자체로 판매수익을 바꾸지 않는다. 1차에는 입고 구매대금이나 폐기 손실을 공통 비용에 자동 추가하지 않는다. 폐기는 수량 기준 기록이다.

**오류:** 유형·날짜·재료 누락, 0 이하 수량, ‘개’ 소수, g/ml 초과 자릿수, 단위 불일치는 저장 불가. 폐기로 기록상 잔량이 음수가 되면 경고 후 명시 확인을 받아 저장한다. 기록번호가 다른 정상 입고가 여러 번 발생할 수 있어 동일 날짜·재료라는 이유만으로 중복으로 단정하지 않는다. 중복 클릭은 별도 중복 저장을 막는다. 재고기록 수정·삭제는 PRD의 1차 필수로 명시되지 않아 새 기능으로 추가하지 않는다. 시안 ‘실사 수정’은 1차에서는 새 실제 수량 확인 창으로 연결한다.

### F10. 실제 재고 확인

**행동:** 재료 행 또는 실사 버튼에서 재료별 실제 수량을 입력한다. ‘이전 실사 이력’은 해당 재료의 기존 실사 기록을 보여 준다.

**입력:** 실사일·재료·실제 수량·사유. 사유는 필수다. 권장 기준은 영업 종료 시점의 실사다. 실제 수량칸은 빈칸으로 시작하며 기록상 잔량을 ‘확인한 값’으로 자동 채우지 않는다.

**처리:** 실사일의 모든 판매·입고·폐기를 반영한 기록상 잔량과 실제 수량의 차이를 계산한다. 저장하면 실제 수량을 새로운 종료 잔량 기준으로 사용한다. 같은 재료·날짜의 추가 실사는 같은 날 재확인으로 알리고 최신 확인량을 운영 기준으로 쓴다. 기존 확인 기록은 남기고 당일 차이를 중복 더하지 않는다.

**결과:** 확인 시점 잔량·실제 확인량·차이·사유를 기록한다. 이후 잔량은 확인량에서 이어진다. 과거 판매·입고·폐기가 바뀌어도 이미 센 수량은 고치지 않는다. 재계산된 차이는 원래 기록한 차이와 구분한다. 저장된 실사에 숫자만 몰래 덮어쓰지 않는다. 실사 차이의 금액은 1차 손익에 자동 반영하지 않는다.

**오류:** 실제 수량 빈칸·음수·단위 위반은 저장 불가. 차이가 0이어도 확인 기록을 남긴다. 날짜상 실사 전후 순서가 달라지면 날짜 기준으로 다시 계산한다. 일중 실사 시각별 적용·전 품목 일괄 확정은 1차에 추가하지 않는다. 기록상 잔량을 계산할 수 없으면 실사 차이를 0으로 만들지 않고 오류를 해결한 뒤 확인하도록 한다.

### F11. 저장과 재접속

**행동:** 판매·비용·재고를 저장한 뒤 화면을 옮기거나 프로그램을 다시 연다.

**처리·결과:** 저장한 기록·기준정보·수수료 기준·마감 확인 상태를 같은 기기에서 유지한다. 입력 중인 미저장 초안은 유지 대상으로 약속하지 않는다. 조회 필터는 운영 기록을 바꾸지 않는다. 저장 상태는 저장 중/저장 완료/저장 실패로 구분한다. 운영 기록 저장과 외부 백업 파일 다운로드는 다른 작업이다.

**오류:** 저장공간 부족·접근 불가·저장 내용 손상이 발견되면 오류를 알리고 성공 표시를 하지 않는다. 재접속 시 초기 샘플로 덮어쓰지 않고 백업 복원 경로를 안내한다. 브라우저·기기 보관 데이터가 삭제되면 파일 백업 없이 복구된다고 약속하지 않는다. 여러 창에서 동시에 수정하는 사용은 지원 범위가 아니며, 별도 창 간 동기화·공동 편집 기능을 추가하지 않는다.

### F12. 전체 백업

**행동:** ‘전체 데이터 백업 파일 다운로드’를 누른다.

**포함 범위:** 자료정보·공급사·재료·메뉴·레시피·가격이력·영업달력·판매·초기재고·재고기록·월비용계획·비용·현재 계산 기준과 변경 후 확인 상태를 전부 포함한다. 과거 판매 원가·수수료와 실측수량을 유지한다. 화면 일부 합계만 내보내거나 일부 묶음을 빠뜨리지 않는다.

**처리·파일 결과:** 한 번에 읽은 저장 완료 상태를 UTF-8 JSON 파일로 만든다. 백업 형식 버전·매장/자료 식별정보·생성 일시·묶음별 실제 건수와 기록을 넣는다. 파일명은 `prep_cafe_backup_YYYYMMDD_HHMMSS.json` 형태다. 파일 생성 중에는 기록 변경을 막아 서로 다른 시점이 섞이지 않게 한다. 파일에는 설정한 기간에 관계없이 전체 기록이 들어간다. 개인정보 익명화·암호화·압축·외부 서비스 전송·자동 스케줄·복원점 이력은 1차에 없다.

**화면 결과:** 다운로드 요청과 대상 파일명을 표시한다. 프로그램이 파일을 만들었다는 것과 사용자가 외부 저장소에 보관했다는 사실은 구분한다. 생성 성공만으로 ‘외부 백업 보관 완료’를 표시하지 않는다.

**오류:** 기록 읽기·파일 생성·다운로드 요청 실패를 구분해 알린다. 운영 기록은 변경하지 않는다. 입력창에 미저장 내용이 있으면 백업에는 저장 완료 기록만 포함된다고 안내한다. 개별 JSON·선택 백업·CSV ZIP 버튼은 1차에 제공하지 않는다.

### F13. 백업 검사와 전체 복원

**행동:** 백업 화면의 파일 선택 또는 끌어 놓기로 본 프로그램의 전체 JSON 백업을 선택한다.

**검사:** 파일 크기 50MB 이하, UTF-8 JSON 해석, 백업 형식 버전 호환, 대상 매장/자료 일치, 필수 묶음·설정 존재, 기록번호 중복, 메뉴·재료·공급사·레시피 연결, 단위·금액·날짜·실측량의 유효성을 검사한다. 생성 시각이 미래면 검사 오류로 안내한다. 최초 자료 JSON은 운영 백업 형식과 다르므로 곧바로 복원 파일로 받지 않는다.

**검사 화면 결과:** 실제 파일명·생성 시각·매장·기록 기간·현재/복원 대상의 묶음별 건수·오류를 표시한다. 건수가 같다고 값도 같거나 무결성이 100%라는 의미로 표시하지 않는다. 파일을 바꿀 때 기존 검사·확인 입력은 초기화한다. 검사 전 복원 버튼은 비활성이다.

**최종 확인:** 모든 운영 기록과 기준·설정이 파일 내용으로 교체되고 병합되지 않는다는 안내를 보여 준다. ‘복원확인’을 사용자가 직접 입력한 뒤 실행 가능하다. 시안처럼 확인 문구를 미리 넣지 않는다. 복원 전 현재 상태의 전체 백업을 만들고 다운로드를 요청하며 사용자가 백업 보관을 확인한 후 교체한다. 이는 복원 보호 절차이며 예약 백업·복원점 관리 기능은 아니다.

**복원 처리·결과:** 준비된 복원 내용을 한 번에 교체한다. 실행 중 입력·중복 실행을 막는다. 성공 후 새 자료로 목록·손익·재고를 재계산하고 초기 기간을 다시 정한다. 원본 백업의 당시 원가·실측량은 보존한다. 이전 자료에서 계산된 표·필터를 그대로 남기지 않는다. 자동으로 새 출력 파일을 만들지는 않는다.

**오류·취소:** 파일 미선택·형식 불일치·누락·다른 매장·지원하지 않는 버전·검사 실패·확인 문구 불일치는 복원 불가. 다른 매장 파일을 현재 매장 이름으로 바꿔 받아들이지 않는다. 음수인 계산상 잔량은 경고 대상이며 유효한 과거 기록을 자동 제거하지 않는다. 교체 전 취소는 기존 상태 유지, 교체 시작 후에는 취소 버튼을 막는다. 교체 실패 시 기존 저장 상태를 유지한다. 유지 여부를 확인할 수 없으면 실패를 알리고 복원 전 백업으로 복구하도록 안내하며 ‘성공’ 또는 ‘즉시 복구 보장’을 표시하지 않는다.

## 7. 채택한 계산 방법

이 절은 이번 FRD에서 채택한 권장안이다. 시안의 숫자를 정답으로 삼지 않는다. 계산에 필요한 원본이 없는 결과는 계산 불가로 표시한다.

### C01. 판매 금액·수수료

- 총 판매금액 = 판매수량 × 판매단가.
- 순매출 = 총 판매금액 − 할인 총액. **결제수수료를 아직 빼지 않은 금액**이다.
- 신규 결제수수료 = 순매출 × 입력 수수료율 ÷ 100. 원 단위로 반올림한다.
- 기존 기록은 보관된 `net_sales`·`payment_fee`를 사용한다. 가격·율 기본값을 바꿔 기존 금액을 덮어쓰지 않는다.
- 금액의 신규 반올림은 0.5원 이상 올림이다. 기존 소수 원가는 보존하고 중간 계산을 원 단위로 잘라내지 않는다. 합계·평균을 표시할 때 원 단위 반올림, 비율은 소수 첫째 자리로 표시한다.

예: 10개 × 4,000원, 할인 총액 2,000원이면 순매출 38,000원. 수수료율 1.5%면 수수료 570원이다. 이 값을 순매출에서 두 번 빼지 않는다.

### C02. 메뉴 원가와 수익성

- 판매일에 유효한 재료 단위원가 = 그 날짜 이전 또는 같은 날짜의 가장 최근 구매가격 ÷ 해당 구매용량.
- 신규 개당 식재료원가 = 적용 레시피의 식재료 사용량 × 해당 단위원가를 모두 더한 값.
- 신규 개당 포장원가 = 적용 채널의 포장재 사용량 × 해당 단위원가를 모두 더한 값. 제공 자료의 I10·I11은 포장재이며 해당 채널 적용 조건을 따른다.
- 레시피 채널이 비어 있으면 모든 채널, ‘포장’이면 포장 판매에만 사용한다. 자료의 R1을 사용한다. 자료에 없는 날짜별 레시피 버전이나 신메뉴를 만들어 적용하지 않는다.
- 기록별 식재료비 = 판매수량 × 당시 개당 식재료원가. 포장재비도 같은 방식이다.
- 메뉴의 남는 금액(공헌이익) = 순매출 − 식재료비 − 포장재비 − 결제수수료.
- 기간 메뉴 이익 = 해당 메뉴·채널·기간 기록의 남는 금액 합계.
- 평균 개당 남는 금액 = 기간 메뉴 이익 ÷ 판매수량 합계.
- 이익률 = 기간 메뉴 이익 ÷ 기간 순매출 합계 × 100. 직접비율 = (식재료비 + 포장재비 + 수수료) ÷ 순매출 × 100.
- 평균 단가·개당 원가·개당 수수료도 각각 금액 합계 ÷ 판매수량 합계. 개별 행 비율의 단순 평균을 쓰지 않는다.

예: 앞의 10개 판매에서 당시 개당 식재료 460원, 매장 판매 포장원가 0원이면 식재료비 4,600원, 남는 금액 32,830원, 이익률 약 86.4%다. 임차료·인건비를 여기에서 또 나누어 빼지 않는다.

### C03. 기간 실적·손익

- 일 조회는 선택 날짜, 월 조회는 그달 1일부터 말일까지다. 양 끝 날짜를 포함한다.
- 기간 순매출·수수료·원가는 기록별 금액을 합산한다.
- 기간 메뉴 이익 = 순매출 합계 − 식재료비 합계 − 포장재비 합계 − 수수료 합계.
- 공통 운영비 = 같은 귀속기간의 비용기록 금액 합계. **월비용계획을 추가 차감하지 않는다.**
- 기록 기준 손익 = 기간 메뉴 이익 − 공통 운영비.
- 손익률 = 기록 기준 손익 ÷ 기간 순매출 × 100. 순매출 0이면 해당 없음.
- 확정 영업일 수 = 달력의 영업 여부와 마감 여부가 모두 예인 날짜 수. 휴무일을 영업일 분모에 넣지 않는다.
- 확정 일평균 순매출 = 확정 영업일의 순매출 합계 ÷ 확정 영업일 수.
- 확정 일평균 손익 = 확정 날짜의 기록 기준 손익 합계 ÷ 확정 영업일 수. 분자의 비용에는 확정된 휴무일에 귀속된 비용도 포함한다. 휴무일은 영업일 분모에는 넣지 않는다. 마감 정보 없음·변경 후 확인 필요 날짜는 확정 평균에서 제외한다.

예: 기간 메뉴 이익 1,000,000원, 비용기록 400,000원, 월계획 600,000원이면 기록 기준 손익은 600,000원이다. 계획까지 빼서 0원으로 만들지 않는다.

### C04. 비용 입력·수정

월 비용 자동 배분은 2차다. 1차 직접 기록은 귀속일에 전액 반영한다. 제공 자료의 이미 배분된 일별 비용은 그대로 사용한다. 기존 같은 날짜·항목 비용을 수정하면 그 행의 변경 전 금액을 제거하고 변경 후 금액을 한 번 반영한다. 삭제하면 그 금액만 제거한다. 지급일이 다른 달이라는 이유로 귀속일을 바꾸지 않는다.

### C05. 기록상 재고 잔량과 실제 확인 기준

- 판매 재료 사용량 = 판매수량 × 적용 채널의 레시피 개당 사용량.
- 첫 기준은 2025-07-01 영업 시작 전 초기재고다.
- 실사가 없는 날짜의 종료 잔량 = 시작 잔량 + 입고량 − 판매 사용량 − 폐기량.
- 실사 전 기록상 잔량은 그날 판매·입고·폐기를 모두 반영한 종료 수량이다. 실사 차이 = 실제 확인량 − 실사 전 기록상 잔량.
- 실사가 있는 날짜의 종료 잔량은 실제 확인량이다. 차이를 더한 다음 실제 확인량을 또 더하지 않는다.
- 다음 날 시작 잔량은 전날 종료 잔량이다. 같은 재료·날짜에 확인이 여러 번이면 최신 저장 확인량을 그날 최종 기준으로 사용한다.
- 실사 이후 잔량은 실제 확인량에 그 이후 날짜의 입고·판매·폐기를 반영한다. 같은 날 기록은 영업 종료 실사 이전에 속한다.
- 과거 기록을 수정하면 날짜 흐름을 다시 계산한다. 실제로 센 수량과 최초에 저장한 차이는 유지하고, 새로 계산한 차이를 별도로 보여 준다. 저장된 실사조정 증감량과 재계산 차이를 함께 더하지 않는다.

예: 초기 원두 1,000g, 입고 500g, 판매 사용 400g, 폐기 100g이면 기록상 잔량 1,000g. 실제 900g을 확인하면 차이는 −100g, 종료 잔량은 900g이다. 다음 날 200g을 사용하면 잔량 700g이다. 이후 실사 전날 판매를 수정해도 실제 확인량 900g은 바꾸지 않는다.

### C06. 폐기·실사 차이의 금액 취급

1차에는 폐기·실사 차이를 수량과 사유로만 반영한다. 이를 메뉴 원가·공통 운영비·별도 손실에 자동으로 중복 넣지 않는다. 가격 기준과 손실 인정 범위가 PRD에서 미정이었으므로, 4시간 핵심 범위에서는 자동 금액 반영을 추가하지 않는 권장 기준을 채택했다. 화면에서 이 제한을 알린다. 재고 시안의 폐기 손실액·감모손실 즉시 손익 반영 설명은 1차에서 사용하지 않는다. 금액 손실을 확장하려면 별도 확인을 받는다.

## 11. 완료 판단과 검사항목

이 문서는 기능 명세이며 실제 구현 검사 결과가 아니다. 구현 후 아래 동작을 확인해야 완료로 판단한다.

1. F01~F13이 모두 접근 가능하고 PRD의 P1-01~P1-07과 연결된다. 비용 목록의 추가·수정·삭제도 누락되지 않는다.
2. 판매를 추가하면 저장 전 미리보기와 저장 후 메뉴 이익·기간 손익·재고가 같은 원본을 근거로 연결된다.
3. 판매 수정·삭제를 반복해도 수수료·재료 차감이 두 번 반영되지 않는다. 현재 가격 변경이 과거 기록을 바꾸지 않는다.
4. 매장·포장의 포장재 적용과 원가 차이가 실제 레시피대로 반영된다. 시안 고정 120원·135원을 사용하지 않는다.
5. 비용 귀속일 기준 손익을 확인한다. 같은 비용의 월계획과 일별 기록을 함께 차감하지 않는다.
6. C01~C05 예제의 수치를 확인한다. 전체 채널 메뉴 이익 합계가 같은 기간 대시보드의 메뉴 이익과 일치한다.
7. 실사 0·음수·빈칸·차이 0, 같은 날 재확인, 실사 전후 날짜 기록 수정의 결과를 확인한다. 실측값과 조정량을 중복 반영하지 않는다.
8. 부분 기간·휴무·미마감·마감 정보 없음·미판매와 누락·순매출 0을 구분한다. 9월 1~18일 확정 영업일 수는 제공 달력 기준 16일이다.
9. 저장 실패 시 성공 표시가 없고 원본이 남는다. 재접속으로 초기 자료가 중복 추가되지 않는다.
10. 새 판매·비용·재고를 저장한 전체 백업을 다른 임시 상태에 복원해 기록 수뿐 아니라 값·당시 원가·실측량·기준정보·설정·재계산 결과가 맞는지 확인한다. 실제 운영 기록을 검사 목적으로 덮어쓰지 않는다.
11. 잘못된 파일·누락·중복번호·다른 매장·크기 초과·확인 문구 불일치·복원 실패에서 원본 유지와 오류 동작을 확인한다.
12. 승인되지 않은 시안의 임시 저장·실제 발주·POS 연동·익명화·보고서 출력·별도 복원점 관리가 새 기능으로 추가되지 않는다.

## 12. 결정 요약과 남은 범위

**이번에 채택한 권장 기준:** 자료와 일치하는 순매출 정의, 수수료 1회 차감, 신규 기본 수수료율 1.5%, 판매·비용 집계 중복 방지, 귀속일 기준 비용, 영업 종료 실사, 실제 수량 기준 재고 재구성, 기록상 음수 경고, 폐기·차이의 자동 금액 손익 제외, 전체 JSON 수동 백업과 검사 후 전체 교체 복원이다. 각 기준은 자료의 사실로 위장하지 않고 이번 기능 명세 결정으로 기록했다.

**추가하지 않은 기능:** 시안의 PRD 밖 기능은 3절·8절에서 구분했다. 이 문서로 승인한 것은 PRD 필수 기능을 완성하는 데 필요한 동작과 계산 기준이다. 후속 새 기능은 사용자 확인 없이 추가하지 않는다.

**후속 단계:** 실제 화면 수정과 비용 목록 설계, 기술·저장 방식·배포 환경, 구현 및 실제 오류 검사다. 2차의 등급·자동화·공유 및 상세 가져오기 정책은 해당 단계에 남겨 두었다. 이번 요청에서는 FRD 파일만 작성했으며 프로그램이나 시안의 동작을 수정하지 않았다.
